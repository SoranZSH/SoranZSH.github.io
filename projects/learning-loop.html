01 / THE REAL PROBLEM

缺的不是更多答案。
是从“看过”到“说得出”的路径。

起点是一个很具体的个人需求：为面试准备专业知识与英文表达。但随着资料增多，问题变成了三件事：学什么、什么时候学，以及怎样才算真的练过。

01

内容会过时，收藏不会自动更新

静态题库无法持续反映 AI 实践的变化。热门项目很多，但“热门”与“值得学习”之间还隔着一次判断。

02

看懂参考答案，不等于能组织表达

先看到答案，很容易产生“我已经会了”的错觉。练习需要一个先独立输出的时刻。

03

提醒越勤，不一定练得越多

会议、笔试、全屏工作时的弹窗，会把学习变成干扰。开始练习的成本和打断的成本，都需要被设计。

产品目标：把寻找内容、整理知识和开始练习的摩擦降下来，让每天的一次主动表达更容易发生。

这是从个人使用需求与开发材料中提炼的问题框架，未开展独立用户访谈或群体效果实验。

02 / THE SYSTEM

两个独立工具。
一条连续的学习路径。

内容端负责发现与维护，练习端负责执行与记录。两者通过稳定的文件格式连接：内容更新可以继续发生，个人练习记录仍由练习端独立管理。

AUTOMATED / 内容供应端

先发现信号，再判断学习价值。

每天定时采集公开仓库，整理 README、版本与依赖等素材，归档进资料库并打成采集包。按语言组计算相对热度，并控制方向集中度；它提供候选，不替人判定技术质量。

OUTPUT采集包 + 项目资料库
明确的数据边界已出题 ≠ 已练过 ≠ 已掌握

采集端读取题库覆盖情况，不读取个人学习历史。完成一次练习只记录行为，不推断能力已经提升。

03 / PRODUCT JUDGEMENT

含金量，藏在取舍里。

这次整理最想保留的，是那些有代价、也有理由的决定。

MY ROLE / 决策与协作的分工

我定义边界，AI 协助实现，验证负责纠偏。

需求记录保留了我确认的约束：采集程序运行时不调用大模型、内容端不能把“已出题”称为“已掌握”、新题必须区分基础与拓展并标明前置。10 月底我又决定把题库从纯 AI 知识扩展到“产品通用轨”（需求、业务架构、信息系统）。

AI 参与代码实现和多轮修订；开发记录则保存问题、候选方案与验收用例。本次复盘重新对照源码，并在隔离副本中执行桌面与采集测试。当前能证明的是规则落地与测试结果，尚不能证明长期学习收益。

查看一条决定如何落到实现

需求决定 D2：系统只能知道“已出题”，不能声称“已掌握”。
实现：采集端读取题库概念覆盖；个人练习历史由练习端独立管理。
产品影响：素材筛选不虚构学习画像，用户完成一次练习也不自动获得“掌握”标签。
依据：《AI 实践采集与题库生成》0.2 节、Github学习 README 与 collector/collect.py。

DECISION 01

自动化搬运信息，把判断留给人。

采集器运行时不调用大模型。素材由人交给 AI 编题，经独立审题，再确认导入。牺牲了“一键全自动”，换来对事实、教学结构和更新范围的控制。

保留：人工质量关口代价：需要编审投入
DECISION 02

内容可以重建，学习记录不能认错人。

AI 为新题写临时编号，导入工具分配正式题号并维护登记。删除或覆盖后不回收旧编号，避免新题继承旧题的练习记录；前置引用与循环依赖在写入前检查。

保留：身份与依赖稳定代价：维护登记与备份
DECISION 03

把“不给答案”，做成第一步。

练习先展示问题和 90 秒计时，再由用户揭晓参考答案。只有明确提交完成或未记住，才计入练习日。关闭窗口不算学过。

保留：主动回忆与明确完成代价：比浏览答案更费力
DECISION 04

一个好提醒，也应该知道什么时候沉默。

结合全屏、系统通知状态、麦克风与摄像头占用判断勿扰；按活跃使用时间安排下一次提醒，结束勿扰后留出缓冲。

保留：情境与用户控制权代价：需要处理系统差异
04 / TRY THE LOOP

少读一段说明。
亲手走一遍。

从一道基础问题开始，先组织表达，再展开参考结构，最后决定是否复习。

每日一题 / 交互演示
F / FOUNDATION01 — RECALL

为什么“模型回答流畅”，
不代表“回答可信”？

Why doesn’t a fluent answer guarantee a reliable one?

90 SEC

先用自己的话解释。
可以中文，也可以英文。

REFERENCE / 示例参考结构

流畅描述的是表达形式，可信还需要事实与证据支持。模型可能生成自然、连贯，却缺乏依据的内容。

  1. 区分目标：语言连贯不等于事实正确。
  2. 解释风险：缺少信息时，也可能给出看似确定的回答。
  3. 落到产品：重要结论需要来源、核验与不确定性提示。
✓

这次，你真的练过了。

基于真实流程重绘 · 示例题目 · 不录音、不评分、不保存练习记录

网页演示不连接原始题库和桌面程序；“明天再练”只展示复习反馈，不创建真实提醒。

05 / ITERATION, NOT A STRAIGHT LINE

真正的过程，
比一条漂亮时间线更曲折。

这是一次事后复盘，而不是把零散开发包装成从第一天就完美规划的路线。现有记录留下了几次明确的方向修正。

START / 个人需求

先让练习发生

从中英双语题库与每日一题切入，加入主动口述、复习排期与情境提醒，让“开始练习”成为可以重复的动作。

RETHINK / 内容重构

从广覆盖，转向可维护的知识结构

旧文档中的广覆盖题库被重新规划。基础 / 拓展、概念键、前置关系与正式编号，成为连接内容生产和练习的共同语言。

BUILD / 2026.10

给知识更新接上来源

公开仓库采集、语言分组、素材打包与资料库逐步落地；内容生产保留人工编审，既有练习工具通过题库契约接入。

LEARN / 真实运行暴露问题

数据口径，比漂亮分数更重要

当天 Star 数据不完整，就排除未结束的当天；英文简介配中文 README 导致误分，就增加正文检测；七天与一天的增量不可比，就改为日均新增。

EXPAND / 2026.10.31

题库扩到 85 题，审题拦下了真问题

一次新增 63 题，覆盖检索增强、智能体，以及需求、业务架构、信息系统三个产品领域。独立审阅退回了两处硬伤：RAG 一组前置链断裂，RRF 的机制被讲反。逐条修正、脚本校验通过、沙盒试导入之后，才正式写入题库。

WHAT CHANGED MY THINKING

而在于它知道哪些结论现在还不能给。
